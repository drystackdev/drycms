# i18n cho admin UI (en/vi) — MVP1

## Context

drycms admin (`src/`) hiện chỉ có text tiếng Anh viết thẳng trong JSX, không có lớp
i18n nào (`grep` không thấy `t(`, `useTranslation`, `i18n`, `locale` ở đâu ngoài
Magic Chat's riêng "AI output language" picker — cái đó chỉ set `lang` gửi cho AI,
không dịch UI). Yêu cầu: thêm khả năng đa ngôn ngữ cho **admin UI** (không phải nội
dung site của từng tenant, không phải seed/mock data — user đã xác nhận "seed không
cần tiếng việt"), theo 5 ràng buộc user đã chốt:

1. Mỗi ngôn ngữ = 1 file `.json` duy nhất, được tải vào IndexedDB.
2. MVP1 cần `en` + `vi`.
3. Dịch toàn bộ admin UI (~24 trang dưới `src/pages/` + các component dùng chung).
4. Dùng tiếng Anh làm key (không tạo id key riêng).
5. Không cần đổi ngôn ngữ realtime — đổi xong reload trang là được.

Codebase đã có sẵn đúng những khối cần để lắp ráp việc này mà **không cần thêm thư
viện i18n** nào (đúng nguyên tắc "prefer API over library"):

- `src/lib/idb-cache.ts` — IndexedDB key/value cache có version, tự nuốt lỗi, không
  bao giờ block render.
- `src/hooks/useFetch.ts` — hook "cache-first qua IndexedDB, rồi fetch mạng theo
  version" y hệt cái ta cần cho "tải 1 file json vào IndexedDB".
- `src/store/theme.ts` — pattern chuẩn cho 1 signal toàn app, seed từ
  `readStoreValue`, persist qua `effect()` + `writeStoreValue` (dùng lại y hệt cho
  `locale`).
- `src/hooks/useStore.tsx` — `drycms:store` blob trong `localStorage`, tự động sync
  cross-device qua `/api/memory` — `locale` chọn sẽ được sync free.

## Thiết kế

### 1. File từ điển

`src/locales/en.json`, `src/locales/vi.json` — flat map `{ [englishKey: string]: string }`.
Key = chính chuỗi tiếng Anh gốc (vd. `"Save"`, `"Delete this entry?"`). `en.json` về
lý thuyết là identity map, nhưng vẫn giữ làm file thật (không suy ra từ key) để sau
này có thể sửa câu chữ tiếng Anh mà không đụng code.

Đây là **source code của app** (giống mọi thứ khác dưới `src/`), commit vào git,
build vào mọi tenant branch — không phải per-tenant content.

**Rủi ro đã biết, chấp nhận cho MVP1**: dùng text làm key nghĩa là 2 chỗ tình cờ
trùng tiếng Anh ("Name" ở field label và "Name" ở cột list) sẽ dùng chung 1 bản
dịch. Nếu gặp trường hợp cần dịch khác nhau, xử lý bằng cách đổi 1 trong 2 chuỗi
tiếng Anh gốc cho cụ thể hơn (vd. "Field name"), không cần xây cơ chế namespacing.

### 2. Đường tải + IndexedDB (tái dùng `useFetch` gần như nguyên bản)

- `src/server/routes/locales.ts` — route mới `GET /api/locales/:lang`, đọc trực
  tiếp từ `src/locales/{lang}.json` (import tĩnh), trả về đúng shape
  `VersionedFetchResult` mà `useFetch` đã định nghĩa (`{ changed, version, data }`).
  `version` = hash nội dung file (deterministic theo nội dung, không cần bump tay).
- `src/lib/i18n.ts` — 1 component nhỏ `LocaleLoader` (render `null`), luôn mount ở
  gốc `App.tsx` (ngang hàng `AuthGate`, để cả trang SignIn/Register cũng có bản
  dịch) gọi `useFetch(`locale:${locale.value}`, fetchLocale)`; khi có `data`, gán
  vào `dict` signal.
- `src/store/locale.ts` — `export const locale = signal<"en"|"vi">(readStoreValue("locale") ?? "en")`
  + `effect()` persist, y hệt `theme.ts`. Thêm `export const dict = signal<Record<string,string>>()`.

Không cần gate loading riêng: lần đầu vào app, `dict.value` là `undefined` trong
một khoảnh khắc rất ngắn (IndexedDB read gần như tức thời) — `t()` fallback về
chính key (tiếng Anh) nên không bao giờ render rỗng, chỉ có 1 lần "chớp" tiếng Anh
trước khi tiếng Việt vào, chỉ ở lần ghé đầu tiên (sau đó cache IndexedDB permanent).
Việc này tận dụng đúng lợi thế của "dùng tiếng Anh làm key": fallback luôn hợp lệ.

### 3. Helper `t()`

```ts
// src/lib/i18n.ts
export function t(key: string, vars?: Record<string, string | number>): string {
  const template = dict.value?.[key] ?? key;
  if (!vars) return template;
  return Object.entries(vars).reduce((s, [k, v]) => s.replaceAll(`{${k}}`, String(v)), template);
}
```

`{name}`-style interpolation tối thiểu, đủ cho các chuỗi động kiểu "Deleted {count}
items" — không cần ICU/pluralization đầy đủ cho MVP1.

### 4. UI chọn ngôn ngữ

Thêm vào `src/pages/Settings.tsx`, cạnh chỗ set theme hiện có: 1 control 2 lựa chọn
(English / Tiếng Việt) ghi `locale.value = ...`, rồi `location.reload()` ngay (đúng
yêu cầu "không cần đổi realtime" → đổi xong reload cho đơn giản, khỏi phải re-render
lại toàn bộ text đang mount).

### 5. Rollout dịch toàn bộ UI

Đây là phần khối lượng lớn — ~24 trang `src/pages/**` + các component dùng chung
(`DryLayout.tsx`, dialogs, field components...) có hàng trăm chuỗi literal. Làm theo
từng lô sau khi hạ tầng (mục 1-4) xong và được duyệt:

1. Dựng hạ tầng + dịch trọn vẹn 1 trang mẫu (`Settings.tsx`, vì control chọn ngôn
   ngữ đã nằm ở đó) để chốt pattern thay `"Save"` → `{t("Save")}` v.v.
2. Quét từng trang còn lại theo lô, mỗi lô: trích chuỗi literal → bọc `t()` → thêm
   entry vào `en.json` (identity) + `vi.json` (bản dịch) → `bun run typecheck`.
3. Theo dõi tiến độ trong `status/i18n.md` (Plan/Status/Speed) vì việc này trải dài
   nhiều phiên làm việc, đúng quy ước CLAUDE.md cho việc nhiều bước.

## File chính sẽ đụng tới

- Mới: `src/locales/en.json`, `src/locales/vi.json`, `src/store/locale.ts`,
  `src/lib/i18n.ts`, `src/server/routes/locales.ts`.
- Sửa: `src/server/handler.ts` (đăng ký route mới, theo pattern các route khác),
  `src/routers/App.tsx` (mount `LocaleLoader`), `src/pages/Settings.tsx` (control
  chọn ngôn ngữ), rồi lần lượt từng file dưới `src/pages/**`, `src/components/**`
  khi quét dịch.

## Kiểm chứng

- `bun run typecheck` sau mỗi lô thay `t()`.
- `bun run dev`, đổi ngôn ngữ trong Settings, reload, xác nhận: (a) label đổi đúng
  theo `vi.json`/`en.json`, (b) DevTools → Application → IndexedDB →
  `drycms-cache` có entry `locale:vi`/`locale:en`, (c) tắt mạng rồi reload — vẫn
  hiện đúng ngôn ngữ đã cache (đúng yêu cầu "tải vào IndexedDB").
- Trang SignIn (trước khi đăng nhập) cũng phải đổi ngôn ngữ được, để xác nhận
  `LocaleLoader` không phụ thuộc `AuthGate`.
